How to create and edit export templates, the template engine, and the data you can use.

{{T .Lang "Export templates"}}
1. What export templates are

An export template turns selected invoices into a file (or files) for your accounting software, or into an HTTP request to an external API. The app ships with 16 prebuilt (system) templates (Rivile, i.SAF, Centas, Apskaita5, Debetas, Finvalda, Euroskaita, Lobasoft, Paulita, Pragma 3/4, StandardERP, Saikas, Agnum, Uniconta, and a generic JSON template).

Operators see templates read-only. Administrators can create, edit, delete and favorite org-owned templates. System templates are read-only for everyone - clone them manually (see below).

2. Creating a template
  1. Go to Settings → Export templates and click Create template (admin only).
  2. Fill in General info: Title (required), Description, Country, Website, Type (File export or API export - locked after creation), Active, Favorite.
  3. On the Files tab (File export) add one or more files. Each file has a filename (the extension decides the download type and the name inside the ZIP) and a content textarea holding the template source.
  4. Use the Preview tab to render the template against a built-in sample invoice before saving. The Preview button re-renders live from the editor.
  5. Click Create template / Save template.
3. Cloning a system template

System templates cannot be edited or deleted (the buttons are hidden and direct POSTs return 403). To customize one: open its Preview page, copy the source from the Template source tab, click Create template, add a file with the same filename, paste and edit the source, then save. There is no one-click clone.

4. The template engine - Go text/template

Templates use the standard Go text/template engine (not Scriban, Handlebars, or Jinja). Core constructs:

  • {{`{{.InvoiceType}}`}} - field on the root payload.
  • {{`{{.FromCompany.Title}}`}} - nested field.
  • {{`{{range $i, $inv := .Invoices}}`}} ... {{`{{end}}`}} - iterate a slice; $i is the index, $inv the element. Index is optional.
  • {{`{{$.InvoiceType}}`}} - always the root payload, even inside a range.
  • {{`{{if .FromCompany}}`}} ... {{`{{end}}`}} - conditional; {{`{{with}}`}}/{{`{{else}}`}} also supported.
  • {{`{{- range ... -}}`}} - a leading/trailing - trims surrounding whitespace. Essential for clean CSV/XML.
  • Comparisons: {{`{{eq .Type "credit"}}`}}, {{`{{gt $a $b}}`}} (eq ne lt le gt ge).

FromCompany and ToCompany are pointers and may be nil. Always guard with {{`{{if $inv.FromCompany}}`}} before accessing their fields.

6. Data available to a template

The root object (. or $) has these fields:

  • .Version, .ExportedAt, .Now - run metadata and current time.
  • .InvoiceType - the grouping chosen for this run: purchases, sales, or all.
  • .Invoices - all selected invoices.
  • .PurchasesInvoices, .SalesInvoices - the purchases/sales buckets (see grouping below).
  • .Companies, .Customers, .Suppliers - parties. Suppliers = sellers (your org companies, Internal: true); Customers = buyers.
  • .InvoiceItems - flat list of every line across all selected invoices.

Each Invoice has: ID, FromCompany, ToCompany, Filename, Checksum, URL, SeriesAndNumber, Type (invoice/credit), OriginalInvoicePublicID, IssueDate, SupplyDate, PaymentDueDate, AmountWithoutVat, VatAmount, AmountWithVat, Currency, Status, Created, Items.

Each Item has: Quantity, Name, Code, UnitPrice, AmountWithoutVat, VatAmount, AmountWithVat, VatRate, Currency, VatClassifier.

Each Company has: Title, Code, VATIdentificationNumber, Street, City, PostalCode, Country, PhoneNumber, Email, Website, BankAccount, Individual, Internal.

Amounts are always float euros in templates (the database stores cents; the export layer converts). Credit notes have all amounts and quantities negated in the payload.

7. Purchases vs Sales grouping

The Invoice grouping selector on the export toolbar decides which bucket invoices land in. It does not filter the selection.

  • Purchases - all selected go into .PurchasesInvoices.
  • Sales - all selected go into .SalesInvoices.
  • All - each invoice is auto-classified by comparing its seller against your org companies; purchases bucket also receives sales invoices.

Most Lithuanian accounting templates iterate .PurchasesInvoices or .SalesInvoices, not .Invoices.

8. Output rules
  • 0 non-empty files → an empty export.txt.
  • 1 non-empty file → downloaded directly; Content-Type from the filename extension.
  • 2+ non-empty files → a ZIP archive named export_YYYYMMDD_HHMMSS.zip.

A file whose rendered content is empty (after trimming whitespace) is dropped. Guard a file with {{`{{- if gt (len .PurchasesInvoices) 0 -}}`}} ... {{`{{- end -}}`}} so it disappears from the ZIP when there is nothing for it.

Extensions: .json → application/json, .xml → application/xml, .csv → text/csv, .txt → text/plain, anything else (e.g. .eip) → application/octet-stream. PDF and HTML output are not supported.

9. API export templates

An API template sends data to an external HTTP endpoint instead of producing a download. The request specification field accepts a JSON object: 

{
  "URL": "https://accounting.example.com/api/invoices",
  "Method": "POST",
  "Headers": {
    "Authorization": "Bearer secret-token"
  },
  "Body": "{{`{{jsonEscape .InvoiceType}}`}}"
}

...or just a plain URL string (defaults to POST, no extra headers, body = full payload JSON). URL, Headers values and Body are all rendered through the same Go text/template engine, so every function above works inside the body. If Body is empty, the whole payload is JSON-marshaled and sent. URLs must be HTTPS and are SSRF-validated (no localhost / private / metadata IPs).

10. Examples

Each example below shows the seller (FromCompany), the buyer (ToCompany), the invoice header, and the line items (Items). Open a system template's Preview page to see these rendered with the sample invoice.

10.1 Complete JSON (export.json) - invoice + both parties + lines:

{
  "version": "{{`{{.Version}}`}}",
  "exported_at": "{{`{{formatDate .ExportedAt "2006-01-02T15:04:05Z07:00"}}`}}",
  "invoice_type": "{{`{{.InvoiceType}}`}}",
  "documents": [
{{`{{- range $i, $inv := .Invoices -}}`}}
    {
      "number": "{{`{{jsonEscape $inv.SeriesAndNumber}}`}}",
      "type": "{{`{{jsonEscape $inv.Type}}`}}",
      "issue_date": "{{`{{formatDate $inv.IssueDate "2006-01-02"}}`}}",
      "currency": "{{`{{jsonEscape $inv.Currency}}`}}",
      "totals": {
        "amount_excl_vat": {{`{{formatFloat $inv.AmountWithoutVat 2}}`}},
        "vat_amount": {{`{{formatFloat $inv.VatAmount 2}}`}},
        "amount_incl_vat": {{`{{formatFloat $inv.AmountWithVat 2}}`}}
      },
      "seller": {
        "name": "{{`{{if $inv.FromCompany}}{{jsonEscape $inv.FromCompany.Title}}{{end}}`}}",
        "code": "{{`{{if $inv.FromCompany}}{{jsonEscape $inv.FromCompany.Code}}{{end}}`}}",
        "vat": "{{`{{if $inv.FromCompany}}{{jsonEscape $inv.FromCompany.VATIdentificationNumber}}{{end}}`}}",
        "country": "{{`{{if $inv.FromCompany}}{{jsonEscape $inv.FromCompany.Country}}{{end}}`}}"
      },
      "buyer": {
        "name": "{{`{{if $inv.ToCompany}}{{jsonEscape $inv.ToCompany.Title}}{{end}}`}}",
        "code": "{{`{{if $inv.ToCompany}}{{jsonEscape $inv.ToCompany.Code}}{{end}}`}}",
        "vat": "{{`{{if $inv.ToCompany}}{{jsonEscape $inv.ToCompany.VATIdentificationNumber}}{{end}}`}}",
        "country": "{{`{{if $inv.ToCompany}}{{jsonEscape $inv.ToCompany.Country}}{{end}}`}}"
      },
      "lines": [
{{`{{- range $j, $item := $inv.Items -}}`}}
        {
          "line_no": {{`{{add $j 1}}`}},
          "description": "{{`{{jsonEscape $item.Name}}`}}",
          "code": "{{`{{jsonEscape $item.Code}}`}}",
          "quantity": {{`{{formatFloat $item.Quantity 4}}`}},
          "unit_price": {{`{{formatFloat $item.UnitPrice 4}}`}},

}

10.3 XML (export.xml) - suppliers master + invoices + both parties + lines:

<?xml version="1.0" encoding="UTF-8"?>
<export version="{{`{{.Version}}`}}" exported_at="{{`{{formatDate .ExportedAt "2006-01-02T15:04:05Z07:00"}}`}}">
  <suppliers>
{{`{{- range $i, $s := .Suppliers -}}`}}
    <supplier>
      <code>{{`{{xmlEscape $s.Code}}`}}</code>

      <country>{{`{{xmlEscape $s.Country}}`}}</country>

{{`{{- end -}}`}}
  </suppliers>
  <invoices>
{{`{{- range $inv := .Invoices -}}`}}
    <invoice>
      <number>{{`{{xmlEscape $inv.SeriesAndNumber}}`}}</number>
      <type>{{`{{xmlEscape $inv.Type}}`}}</type>
      <issue_date>{{`{{formatDate $inv.IssueDate "2006-01-02"}}`}}</issue_date>
      <seller>
        <name>{{`{{if $inv.FromCompany}}{{xmlEscape $inv.FromCompany.Title}}{{end}}`}}</name>
        <vat>{{`{{if $inv.FromCompany}}{{xmlEscape $inv.FromCompany.VATIdentificationNumber}}{{end}}`}}</vat>
      </seller>
      <buyer>
        <name>{{`{{if $inv.ToCompany}}{{xmlEscape $inv.ToCompany.Title}}{{end}}`}}</name>
        <vat>{{`{{if $inv.ToCompany}}{{xmlEscape $inv.ToCompany.VATIdentificationNumber}}{{end}}`}}</vat>
      </buyer>
      <totals excl_vat="{{`{{formatFloat $inv.AmountWithoutVat 2}}`}}" vat="{{`{{formatFloat $inv.VatAmount 2}}`}}" incl_vat="{{`{{formatFloat $inv.AmountWithVat 2}}`}}"/>
      <lines>
{{`{{- range $item := $inv.Items -}}`}}
        <line description="{{`{{cdata $item.Name}}`}}" qty="{{`{{formatFloat $item.Quantity 4}}`}}" net="{{`{{formatFloat $item.AmountWithoutVat 2}}`}}" vat_rate="{{`{{formatFloat $item.VatRate 2}}`}}" classifier="{{`{{xmlEscape (defaultStr "PVM1" $item.VatClassifier)}}`}}"/>
{{`{{- end -}}`}}
      </lines>
    </invoice>
{{`{{- end -}}`}}
  </invoices>
</export>

10.4 API template body - render a JSON document inside the request body:

{
  "URL": "https://accounting.example.com/api/invoices",
  "Method": "POST",
  "Headers": {
    "Authorization": "Bearer secret-token",
    "Content-Type": "application/json"
  },
  "Body": "{\"batch\":\"{{`{{jsonEscape .InvoiceType}}`}}\",\"count\":{{`{{len .Invoices}}`}},\"exported_at\":\"{{`{{formatDate .ExportedAt "2006-01-02T15:04:05Z07:00"}}`}}\"}"
}

For non-trivial bodies, iterate .Invoices inside Body (as in 10.1) instead of hand-escaping. If Body is empty, the whole payload is JSON-marshaled and sent.

10.5 Fixed-width text (report.txt) - using printf for padding:

{{`{{- range $inv := .Invoices -}}`}}
{{`{{printf "%-15s" (truncate $inv.SeriesAndNumber 15)}} | {{formatDate $inv.IssueDate "2006-01-02"}} | {{printf "%10s" (formatFloat $inv.AmountWithVat 2)}} {{printf "%-3s" $inv.Currency}}`}}
{{`{{- end -}}`}}

11. Troubleshooting
Symptom Likely cause / fix
parse template error in previewUnbalanced {{`{{}}`}} or unknown function. Match braces and use only the functions in section 5.
render template error in previewNil-pointer on FromCompany/ToCompany. Guard field access with {{`{{if $inv.FromCompany}}`}}.
File missing from the ZIPIts rendered content trimmed to empty (expected when guarded). Remove the guard or ensure data exists.
Numbers quoted in JSONUse {{`{{formatFloat $x 2}}`}} without quotes for numbers; reserve "{{`{{jsonEscape ...}}`}}" for strings.
Trailing comma breaks outputAdd {{`{{if not (last $i (len $.Invoices))}},{{end}}`}} after each element.
API export SSRF errorUse a public HTTPS endpoint; private/loopback/metadata IPs are blocked.
Edit/Delete buttons missingSystem templates are read-only (clone manually), or you are signed in as an operator (read-only by design).
Wrong VAT rate / code in outputFix the line's VAT classifier on the invoice review page; the export follows the classifier.
